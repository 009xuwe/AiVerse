# Custom Panel (DIY Dashboard) & Adaptive Cards Design Spec

This document defines the **Adaptive Cards declarative micro-template spec** that AiVerse supports in the "Custom Panel (DIY Dashboard)" above the chat input box.

Following this spec, AI assistants and developers can write panel scripts (Python / Node / Shell) that output structured card JSON, fully customizing the panel's layout, colors, progress bars, metric cards and detail info in both the collapsed state (Compact) and the expanded state (Expanded).

Click the panel title above the chat input box to expand or collapse it. The expanded body takes up at most about 40% of the available height of the chat area; when content is long, scroll up and down inside the body to see all of it, while the top title and the collapse button stay fixed and the input box remains below the panel. Short panels display at their actual content height, so there's no need to truncate detail lists in your script.

## 1. Script Storage Path & Management

### 1.1 Default Storage Path
- **Unified script directory**: `~/.aiverse/scripts/`. In local mode this is `/root/.aiverse/scripts/` inside the container, mapped to the host app's data directory and preserved across container upgrades/reinstalls; in remote mode it is `~/.aiverse/scripts/` under the server user's home (the remote is authoritative; both reads and writes happen on the remote).

### 1.2 Writing Scripts & Language Support
A script only needs to output the standard JSON result to **standard output (stdout)**:
- **Python scripts** (`.py` suffix): the underlying layer automatically runs `python3 <script_path>`;
- **NodeJS scripts** (`.js` suffix): the underlying layer automatically runs `node <script_path>`;
- **Shell scripts** (`.sh` / `.bash` suffix): the underlying layer automatically runs `bash <script_path>`;
- **Binary / executable scripts**: if they have execute permission (`chmod +x`), the underlying layer executes them directly.

### 1.3 Path Resolution Rules
In the provider setting "Panel script", the following path formats are supported:
1. **Bare file name** (recommended, e.g. `demo_balance.py`): automatically looked up under the `~/.aiverse/scripts/` directory;
2. **Relative path** (e.g. `scripts/my_panel.py` or `.aiverse/scripts/my_panel.py`): automatically expanded from `~/.aiverse/`;
3. **Tilde path** (e.g. `~/.aiverse/scripts/my_panel.py` or `~/my_script.py`): automatically expanded to the home of the current execution environment (`/root` for the local container, the server user's home for remote);
4. **Absolute path inside the container** (e.g. `/root/workspace/scripts/quota.py`).

## 2. Script Runtime Environment & Injected Environment Variables

When a panel script runs, AiVerse automatically injects the following environment variables, which the script can freely consume to build a dynamic panel:

### Token Variables

> **Note on "input tokens"**: `LAST_INPUT_TOKENS` and `TOTAL_INPUT_TOKENS` are both the **total input tokens** returned by the API (i.e. `input_tokens` / `prompt_tokens` / `promptTokenCount`), **already including cache-hit portions**. `LAST_CACHED_TOKENS` is the portion of those that hit the server-side cache (a subset). Therefore, net new input = `LAST_INPUT_TOKENS` - `LAST_CACHED_TOKENS`.
>
> **Note on model variables**: the `AIVERSE_MODEL_*` series in the table below follows the **current channel** — the custom context window, unit price and capability switches you fill in for that model under Provider → Model take effect directly; only fields you leave empty fall back to automatic detection.

#### Custom Script Parameters (Panel / DIY Scripts)

In "Provider edit → Panel (DIY)" you can configure any number of custom script parameters (Key-Value).
When the panel script runs, each parameter is injected into the script's environment as `AIVERSE_KEY_<KEY>`:

- KEY is normalized to **uppercase**, keeping only letters, digits and underscores, e.g. ACCOUNT_ID → AIVERSE_KEY_ACCOUNT_ID;
- Keys are case-insensitive; on conflict, the one added later wins;
- Parameter values support referencing the current provider's config placeholders, avoiding repeated entry of sensitive info such as API keys.

::: v-pre
| Placeholder | Description |
| :--- | :--- |
| {{PROVIDER_API_KEY}} | Currently active API key |
| {{PROVIDER_ID}} | Provider record ID |
| {{PROVIDER_NAME}} | Provider name |
| {{PROVIDER_TYPE}} | Upstream format (OPENAI / ANTHROPIC / GEMINI) |
| {{BASE_URL}} | Provider base URL |
| {{DEFAULT_MODEL}} | Default model |
| {{SELECTED_MODEL}} | Currently selected model |
| {{MODEL}} | Actually effective model (selected first, then default) |
:::

Example: with parameter KEY=ACCOUNT_ID and VALUE=<span v-pre>{{PROVIDER_API_KEY}}</span>, the script gets
AIVERSE_KEY_ACCOUNT_ID=<current API key>.

## 3. Design Philosophy & Architecture Principles

- **Declarative UI**: the script only outputs a JSON description tree via standard output; it never touches Android native drawing code.
- **Pure native Compose rendering**: parsing and drawing are handled by a native Jetpack Compose component tree, keeping expand/collapse animations smooth.
- **Automatic theme adaptation**: all semantic colors (e.g. `Good`, `Warning`, `Attention`, `Accent`, `Subtle`) automatically follow the app's light/dark theme; no need to hardcode multiple themes.
- **Dual-State Architecture**:
  - **Compact View**: a compact single-line entry above the input box (about 28dp~34dp tall), used to persistently show core remaining quota or status.
  - **Expanded View**: the rich card panel shown after expanding (adaptive height), supporting multi-column grids, itemized bills, large metric blocks and action buttons.
- **Event-driven real-time refresh**:
  - **Instant refresh on every LLM request**: within the Agent workflow, each time a single API request completes (yielding the latest input/output tokens), the app automatically re-runs the script with the latest context and refreshes the panel;
  - **Page entry & manual refresh**: entering a session for the first time, editing the script in settings, or clicking the panel's refresh button all trigger an immediate refresh.

## 4. Root Structure Definition (Root Card Schema)

A panel script's standard output should produce the following root structure:

```json
{
  "type": "AdaptiveCard",
  "version": "1.5",
  "compact": {
    "type": "Row",
    "items": [ ... ]
  },
  "body": [ ... ]
}
```

### Root Field Reference

| Field | Type | Required | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `type` | String | Yes | - | Always `"AdaptiveCard"` |
| `version` | String | No | `"1.5"` | Spec version; `"1.5"` recommended |
| `compact` | Container | No | `null` | **Compact-state** content (a single-line compact container). If omitted, the system automatically extracts the first 2~3 key metrics from `body` to generate it |
| `body` | Array | Yes | `[]` | **Expanded-state** card body containers and component tree. Interactive elements such as buttons also go in `body` (see `ActionButton` below) |

## 5. Complete Component & Container Reference (Elements Reference)

### 5.1 Container & Layout Components

> **Universal `visible` property**: every component accepts `"visible": false` to hide that element; it is skipped at parse time and not rendered. Useful for dynamically controlling visibility based on environment variables.

#### `ColumnSet` (multi-column grid container)
Lays out child elements side by side in multiple horizontal columns; the core container for building multi-period metrics and left/right comparison cards.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Fixed `"ColumnSet"` | - |
  | `columns` | Array<Column\> | `[]` | List of column objects |
  | `spacing` | String / Number | `"Medium"` | Column-gap enum or number (e.g. `8`, `"10dp"`) |
  | `gap` | Number / String | `null` | Exact gap between columns (e.g. `8`, `"12dp"`); takes precedence over `spacing` |
  | `padding` | Number / Array / Object | `null` | Container inner padding (e.g. `8`, `[4, 8]` or `{ "top": 4, "right": 8 }`) |
  | `margin` | Number / Array / Object | `null` | Container outer margin |
  | `minHeight` | Number / String | `null` | Minimum height constraint (e.g. `48`, `"48dp"`) |
  | `horizontalAlignment` | String | `"Left"` | Horizontal alignment: `"Left"`, `"Center"`, `"Right"` |

#### `Column` (single column)
A child of `ColumnSet`; stacks content components vertically inside it.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Fixed `"Column"` | - |
  | `width` | String / Number | `"stretch"` | Width mode:<br>• `"auto"`: fit content to minimum width<br>• `"stretch"`: share remaining available space equally<br>• numeric values like `"1"`, `"2"`, `"3"`: flex weight ratio<br>• `"50px"`, `"50dp"`: fixed width |
  | `separator` | Boolean | `false` | When `true`, shows a thin vertical divider between this column and the previous one |
  | `spacing` | String | `"None"` | Vertical gap enum between children inside the column: `"None"`, `"Small"`, `"Medium"`, `"Large"` |
  | `gap` | Number / String | `null` | Exact vertical gap between children inside the column (e.g. `4`, `"6dp"`); takes precedence over `spacing` |
  | `padding` | Number / Array / Object | `null` | Column inner padding (e.g. `4`, `[2, 4]`, etc.) |
  | `minHeight` / `maxHeight` | Number / String | `null` | Min/max height constraint |
  | `minWidth` / `maxWidth` | Number / String | `null` | Min/max width constraint |
  | `verticalContentAlignment` | String | `"Top"` | Vertical alignment within the column: `"Top"`, `"Center"`, `"Bottom"` |
  | `items` | Array<Element\> | `[]` | List of components stacked vertically in the column |

#### `Container` (generic block container)
Used to bundle several elements into a standalone card, highlighted block or grouped background.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Fixed `"Container"` | - |
  | `style` | String | `"Default"` | Container style: `"Default"`, `"Subtle"`, `"Emphasis"`, `"Good"`, `"Warning"`, `"Attention"`, `"Accent"` |
  | `bleed` | Boolean | `false` | Whether to extend to the parent container's edges |
  | `spacing` | String / Number | `"None"` | Gap between the container and the element above it |
  | `gap` | Number / String | `null` | Vertical gap between children inside the container (e.g. `6`, `"8dp"`) |
  | `padding` | Number / Array / Object | `null` | Container inner padding |
  | `margin` | Number / Array / Object | `null` | Container outer margin |
  | `cornerRadius` | Number / String | `null` | Custom background and border corner radius (e.g. `8`, `"8dp"`) |
  | `minHeight` / `maxHeight` | Number / String | `null` | Container height constraint |
  | `minWidth` / `maxWidth` | Number / String | `null` | Container width constraint |
  | `items` | Array<Element\> | `[]` | Child component tree inside the container |

#### `Row` (single horizontal row)
Used to lay out several small elements (e.g. label + status dot + text) compactly in one horizontal row; commonly used for the `compact` collapsed state.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Fixed `"Row"` | - |
  | `spacing` | String / Number | `"Small"` | Gap enum or value between children in the row |
  | `gap` | Number / String | `null` | Exact gap between children (e.g. `4`, `"6dp"`) |
  | `padding` / `margin` | Number / Array / Object | `null` | Inner/outer padding |
  | `verticalAlignment` | String | `"Center"` | Vertical alignment: `"Top"`, `"Center"`, `"Bottom"` |
  | `items` | Array<Element\> | `[]` | List of child elements laid out horizontally |

> **Row child weight**: each child in a Row can pass an extra `"weight"` numeric property to control its flex width ratio. For example `{ "type": "TextBlock", "text": "...", "weight": 2 }` makes that text block take 2 shares of width. Column / ColumnSet default to `weight=1` when unspecified; other types don't stretch by default.

#### `Spacer` (blank placeholder)
Explicitly inserts blank space, used to precisely control spacing between elements in a Row / Column / Container.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Fixed `"Spacer"` | - |
  | `height` | Number / String | `null` | Fixed height (dp); effective in Column / Container |
  | `width` | Number / String | `null` | Fixed width (dp); effective in Row |

> When both are omitted it defaults to a `Small` height. For flexible spacing in a Row, use the `weight` property of Row children instead.

#### `FlowRow` (auto-wrapping flow layout)
Children are laid out horizontally and wrap automatically; suitable for badge groups, tag lists and other cases with a variable number of items.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Fixed `"FlowRow"` | - |
  | `items` | Array<Element\> | `[]` | List of child elements |
  | `gap` | Number / String | `null` | Horizontal gap (dp) |
  | `verticalGap` | Number / String | `null` | Vertical gap after wrapping (dp) |
  | `padding` / `margin` | Number / Array / Object | `null` | Inner/outer padding |
  | `minHeight` / `maxHeight` | Number / String | `null` | Height constraint |

#### `ScrollRow` (horizontally scrollable container)
Children are laid out horizontally and can be scrolled; suitable when content exceeds the screen width.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Fixed `"ScrollRow"` | - |
  | `items` | Array<Element\> | `[]` | List of child elements |
  | `gap` | Number / String | `null` | Gap between children (dp) |
  | `padding` / `margin` | Number / Array / Object | `null` | Inner/outer padding |
  | `minHeight` / `maxHeight` | Number / String | `null` | Height constraint |

#### `TabSet` (tab container)
Shows multiple groups of content by switching tabs in a limited space; suitable for paging remaining quota, tokens, cost and similar info.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Fixed `"TabSet"` | - |
  | `tabs` | Array<Tab\> | `[]` | Array of tabs |
  | `tabPosition` | String | `"top"` | Tab bar position: `"top"` / `"bottom"` |
  | `tabStyle` | String | `"primary"` | Tab bar style: `"primary"` (Material indicator) / `"pills"` (pill buttons) |
  | `indicatorColor` | String | `null` | Accent color for the selected state (semantic color or hex); affects the indicator/pill/selected text |
  | `tabBackgroundColor` | String | `null` | Tab bar background color (semantic color or hex) |
  | `tabContentColor` | String | `null` | Text color of unselected tabs (semantic color or hex) |
  | `cornerRadius` | Number / String | `null` | Pill corner radius (dp) for the `pills` style |
  | `padding` / `margin` | Number / Array / Object | `null` | Inner/outer padding |

- **Tab child properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Fixed `"Tab"` | - |
  | `label` | String | `""` | Tab title text |
  | `icon` | String | `null` | Tab icon name (e.g. `"external-link"`, `"copy"`, `"help"`) |
  | `badge` | String | `null` | Small badge text at the tab's top-right corner (e.g. `"3"`, `"!"`) |
  | `color` | String | `null` | Accent color when this tab is selected (semantic color or hex; takes precedence over TabSet's `indicatorColor`) |
  | `items` | Array<Element\> | `[]` | List of child components under this tab |

> **Compact-state behavior**: in compact mode a TabSet doesn't render the tab bar and only shows the first tab's content.

### 5.3 Interactive Button (ActionButton)

Buttons can be placed as ordinary elements anywhere in `body` (Row / Column / Container / FlowRow, etc.), replacing the old root-level `actions` field.

#### `ActionButton` (clickable button)
Opens an external link or copies text to the clipboard on click.

- **Properties**:
  | Property | Type | Required | Default | Description |
  | :--- | :--- | :--- | :--- | :--- |
  | `type` | String | Yes | - | Fixed `"ActionButton"` (aliases `"button"`, `"action"`) |
  | `title` | String | Yes | - | Button text (e.g. `"Top up"`, `"Copy key"`) |
  | `action` | String | No | `"openUrl"` | Behavior type: `"openUrl"` (open link) / `"copy"` (copy text) / `"refresh"` (refresh panel) |
  | `url` | String | Conditional | - | Required when `action=openUrl`; a full HTTP/HTTPS link |
  | `value` | String | Conditional | - | Required when `action=copy`; the text content to copy |
  | `icon` | String | No | `null` | Name of the icon before the button (e.g. `"external-link"`, `"copy"`) |
  | `style` | String | No | `"Default"` | Button background style: `"Default"` (solid light), `"Subtle"`, `"Good"`, `"Warning"`, `"Attention"`, `"Accent"` |
  | `color` | String | No | `"Accent"` | Button text/icon color (semantic color or hex) |
  | `padding` / `margin` | Number / Array / Object | No | `null` | Inner/outer padding |

Example:

```json
{
  "type": "Row",
  "items": [
    { "type": "TextBlock", "text": "Balance low?", "weight": 1 },
    {
      "type": "ActionButton",
      "title": "Top up",
      "action": "openUrl",
      "url": "https://api.openai.com",
      "icon": "external-link",
      "style": "Accent",
      "color": "Accent"
    }
  ]
}
```

## 6. Color Spec & Theme Mapping

Adaptive Cards use a semantic color system to ensure strong contrast and good visual quality in both light mode and dark mode:

| Semantic Color | Light Theme Look | Dark Theme Look | Typical Use Case |
| :--- | :--- | :--- | :--- |
| **`Good`** | Emerald green `#10B981` | Fresh light green `#34D399` | Healthy balance, ample quota, service normal |
| **`Warning`** | Amber orange `#F59E0B` | Bright orange-yellow `#FBBF24` | Quota below 20%, rate limiting imminent |
| **`Attention`** | Rose/alert red `#EF4444` | Light alert red `#F87171` | Quota exhausted, suspended for non-payment, script query error |
| **`Accent`** | Brand blue/tech purple `#3B82F6` | Light tech blue `#60A5FA` | Key metric highlight, secondary periods, normal progress |
| **`Default`** | Dark gray-black `#1F2937` | Off-white gray `#F3F4F6` | Main titles, core big-number amounts |
| **`Subtle`** | Muted gray `#6B7280` | Secondary light gray `#9CA3AF` | Auxiliary units, subtext, converted exchange rates |

## 8. Design Tips for AI Assistants Writing Panel Scripts

1. **Use the injected environment variables**:
   Read the real token data for each single request via `os.environ.get("AIVERSE_LAST_INPUT_TOKENS", "0")` and the like, then seamlessly assemble that request's token consumption, cache-hit rate or cost estimate.
2. **Layer the information**:
   - Keep `compact` to a single refined line (e.g. `[🟢 OK] 5h: 80% | $18.42`);
   - Provide multi-column expansion, billing details and action buttons in `body`.
3. **Handle errors gracefully**:
   On network timeout or API error, output a card with `StatusDot(color="Attention")` and a friendly error notice.
